# 后端召回恢复：设计

保持 `app_seen_names` 为用户曝光的唯一判据；模型审稿记录不参与用户发卡去重。`app_attempts` 增加最近成功审稿时间，老数据初始时间设为 epoch；每轮先召回从未审过的名字，再用距离上次审稿至少一小时的未入库名字补足 25 个。模型请求失败不更新审稿时间。来源无可用候选时按照一小时到期时间退避。

原文准入为 `已核验且 can_generate=1` 或 `待核验`；`不采用`、已核验但停用者不可生成或发卡。召回在代码里先筛除空白、标题式及非正文片段。东亚年号只从冒号前的年号名称取字，并保留相对于原文的位置。模型 85 分门槛保持不变。

新迁移将物料唯一键从 `(profile_id,given_name)` 调整为 `(profile_id,given_name,book)`，不删除历史物料。发卡查询在同一批内按 `given_name` 去重，保留跨来源库存与用户曝光的全来源唯一性。停生产器、备份 PostgreSQL、迁移、更新 API/生产器、复核库存和发卡，按这个顺序上线。

模型日调用限额作为部署配置，避免待核验原文放开后无限调用；具体额度由用户确认。
