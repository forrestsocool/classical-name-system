# 古籍智能起名系统

基于古籍典故、音形义和大语言模型筛选的中文起名网站。

## 项目能力

- 从《论语》《礼记》《尚书》《楚辞》《周易》《孟子》《庄子》《诗经》《周礼》中检索典故。
- 汇总中国、朝鲜半岛、越南、日本历史年号，支持年号搜索和详情查看。
- 支持单姓、复姓、单字名、双字名、固定字、避用字和名字排除。
- 起名前只填写姓氏、字数、固定字和避用字；文化气质由模型结合释义归纳到结果标签。
- 后台按九部古籍轮换生产，最多8路并发，每个请求审读同一本书的25个连字候选；单批完成立即入库，不等最慢请求。
- 模型只做适名审稿、评分和释义，75分以上才能入池；来源分配由服务端独立控制，发卡优先补足近期少见的书籍，再打散重复用字。
- 五行只在结果中依据已核验字属性作解释；资料不足时标为未知，不据名字推断宝宝八字。保留独立历法接口供其他用途。
- 设备指纹与随机会话共同标识用户，持久化布隆过滤器加精确曝光表去重；同一个名字不会因为换来源而再次推荐。主动撤回是例外，清除设备数据会产生新身份。
- 支持收藏、比较、反馈、历史任务和管理复核流程。
- 发现、收藏、设置合并到顶栏；固定高度卡片、独立详情底部面板、热门提醒折叠，避免详情展开挤动卡片。
- 左滑跳过、右滑收藏；支持距离或速度触发、斜滑、取消回弹、键盘、按钮和一次撤回。下一张立即可操作，不等待离场动画。
- 姓氏和条件记在本机；每个标签页独立缓存有效租约，刷新续看。卡片区域拦截浏览器缩放手势，输入字号至少16像素；其他区域保留辅助缩放能力。
- 同条件用户共享合格物料池，固定字或关键词使用用户私有临时池，默认闲置5分钟回收；未看的预加载卡不计曝光，租约到期可重新投递。
- 前端低于16张时取库存，每次最多8张；后台维持每个活跃用户约72张未看库存，90秒没有活跃心跳停止补给。默认全站每日最多派发480批，限制持续消耗。
- 每张卡片携带生成任务编号；右滑立即进入下一张，收藏异步保存，失败留在本地待同步队列，可手动或联网后重试。管理密钥和模型密钥不写入滑卡缓存。
- 读取本地公安部全国姓名报告参考资料；历史热门字、热门名提醒收在“典故、热度与五行参考”的折叠内容中，不干扰滑卡。
- 支持兼容聊天补全格式的大语言模型接口；返回编号必须属于召回池，无法编造出处或改写名字。
- 支持就绪检查、健康检查、请求限流、质量统计、数据库备份和反向代理。

## 技术栈

- 前端：原生 HTML、CSS、JavaScript
- 后端：Python、FastAPI、Uvicorn
- 数据库：SQLite
- 历法：`lunar-python`
- 拼音：`pypinyin`
- 模型接口：兼容 OpenAI `chat/completions` 的 JSON 接口
- 部署：Caddy 或其他反向代理

## 快速运行

在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r 后端/requirements.txt
$env:起名管理密钥 = "请替换为至少16位ASCII密钥"
python 脚本/部署检查.py
python -m uvicorn 后端.起名服务:应用 --host 127.0.0.1 --port 8000
```

打开 `http://127.0.0.1:8000`。

也可以执行：

```powershell
$env:起名管理密钥 = "请替换为至少16位ASCII密钥"
.\启动服务.ps1
```

`起名管理密钥`必须至少 16 个字符，并且只能使用 ASCII 字符。不要把真实密钥写入 Git。

## 配置

`.env.example` 是配置模板。模型可通过网页“资料管理 → 模型接口设置”修改，需要管理密钥。保存于已忽略的 `构建产物/运行数据/模型配置.json`，优先于环境变量；可用 `起名模型配置文件` 指定其他路径。没有配置文件时读取环境变量：

```powershell
$env:起名管理密钥 = "替换为随机生成的长密钥"
$env:起名每分钟上限 = "60"
$env:起名模型地址 = "https://api.openai.com/v1/chat/completions"
$env:起名模型密钥 = ""
$env:起名模型名称 = ""
```

模型配置说明：

- 必须配置有效模型接口。鉴权、超时或响应校验失败时返回错误，不将原文碎片作为候选展示。
- 网页读取配置不回显密钥；留空可保留旧密钥，更换地址时必须重新填密钥。校验错误也不回显请求正文。
- 仅允许公共HTTPS模型地址并拒绝重定向；密钥只随服务端请求发往管理员指定服务。服务器文件权限仍需由部署者管理。
- 召回和重排的随机种子可复现，但第三方模型的结果不保证完全可复现；不同批次也不保证无限不重复。
- 模型主筛选仍需人工抽样评估质量。自动化测试使用模拟模型，不要求开发或CI持有真实密钥。

后台补给配置（单工作进程）：

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `起名后台生产` | `1` | 设为 `0` 只消费库存，不调用后台模型 |
| `起名队列库存` | `72` | 每个活跃用户的未看库存目标 |
| `起名每日生产批次` | `480` | 全站每日派发上限，包含失败批次；UTC零点重置 |
| `起名临时队列秒数` | `300` | 固定字私有队列无访问后的回收时间 |

生产只在有需求时启动，不是全天无限生成。首次冷启动、库存耗尽、上游故障或触及额度时仍可能等待；不以不合格名字填空。具体机制见 [队列与滑卡优化方案](队列与滑卡优化方案.md)。

## 参考资料和数据库

原始资料位于 `古籍与东亚年号参考资料/`，原文不直接覆盖。数据库文件为 `构建产物/起名系统.sqlite3`，主要表包括：

- `sources`、`books`、`passages`：来源、古籍、古籍片段
- `eras`：中国、朝鲜半岛、越南、日本历史年号，含来源行、记录类型和人物字段
- `directions`、`direction_keywords`：文化方向和关键词
- `candidate_phrases`：典故候选词组
- `characters`、`character_elements`：汉字、拼音和五行规则
- `audit_issues`：资料审计问题
- `name_runs`、`candidates`：起名任务和候选名字
- `model_candidates`、`model_metrics`：模型候选和调用指标
- `favorites`、`feedback`：收藏、比较和反馈
- `feed_pools`、`feed_materials`、`feed_sources`、`feed_attempts`：队列、合格物料、来源进度、已审候选
- `feed_subscribers`、`feed_leases`、`feed_receipts`、`feed_deliveries`：活跃订阅、临时投递、幂等回执和离线确认凭据
- `feed_exposures`、`feed_blooms`、`feed_budget`：精确曝光、布隆位图和持久化生产额度

队列表首次访问时自动增量创建，不重建原有资料、收藏和历史。使用SQLite在线备份脚本备份运行库；运行时启用WAL，不要只复制正在写入的主数据库文件。

姓名报告热度资料不写入 SQLite，而是随代码发布在 `公安部姓名报告参考资料/公安部姓名报告热度.json`，服务启动后本地读取并缓存。这样不依赖外网，也不会把实时人口数据误称为报告数据。当前纳入 2018—2021 统计年度的全国新生儿热门字和热门名；2022、2023 年按本次核验未纳入未经官方原文确认的数据。

重新审计、建库和生成复核清单：

```powershell
python 脚本/审计参考资料.py
python 脚本/生成复核清单.py
python 脚本/生成诗经篇章结构.py
python 脚本/核验周易字形.py
python 脚本/建立资料数据库.py
```

备份数据库：

```powershell
python 脚本/备份数据库.py
```

备份文件放在 `构建产物/数据库备份/`，该目录不会提交到 Git。

当前数据库基线：9 部古籍、8554 个古籍片段、2099 条历史年号、10 个典故词组、5829 个汉字记录。

`构建产物/诗经篇章结构.json` 已按原始行号整理出 305 篇、30 个分区和正式篇名。正式篇名配置位于 `资料配置/诗经正式篇名.json`，六篇有题无辞的笙诗只保留目录说明，不伪造正文。

`构建产物/周易字形核验.json` 逐字记录 79 个“干”字的语境建议，已完成“乾”与“干”的语境分类。`构建产物/展示资料/周易-规范化展示.txt` 只应用高置信“乾”字建议，原始正文仍保留，避免把“干事”“干城”等不同义项误改。

生产发布使用 `部署/prometheus.yml` 抓取 `/metrics`，`部署/起名系统告警.yml` 提供目标不可用、错误率和耗时告警。发布前执行 `python 脚本/生产压测.py --地址 http://127.0.0.1:8000 --请求数 10 --并发数 3`，脚本会验证健康、就绪、检索、起名四类请求，并清理压测任务。

### 管理接口

管理接口必须携带 `X-Admin-Key` 请求头：

- `GET /api/admin/review-queue`：古籍片段复核队列
- `POST /api/admin/passages/{id}/review`：复核古籍片段
- `GET /api/admin/element-queue`：汉字五行复核队列
- `POST /api/admin/characters/{char}/element-review`：复核汉字五行
- `GET /api/admin/audit-queue`：资料审计问题队列
- `POST /api/admin/audit-issues/{id}/review`：处理审计问题
- `GET /api/admin/metrics`：查看反馈、模型调用和成本统计
- `GET /api/admin/feed-metrics`：查看来源合格数、库存、生产中任务及今日批次；网页“资料管理→查看来源与库存”可访问
- `GET /api/admin/model-config`：读取模型配置（不返回密钥）
- `PUT /api/admin/model-config`：保存接口、模型和密钥，下一次调用生效

## 起名流程

```text
条件 -> 共享池 / 固定字私有池 -> 活跃消费者与库存水位
                               ↓ 按需生产
九部古籍轮换 -> 单书连字召回25个 -> 最多8路模型审稿
                               ↓ 每批独立完成
编号与质量校验 -> 释义、五行及热度解释 -> SQLite合格物料池
                               ↓ 短请求取库存
曝光精确去重 -> 近期来源平衡与重字打散 -> 临时租约 -> 前端卡片栈
                               ↓ 真正显示时确认
                     曝光记录与布隆过滤器持久化
```

旧的 `/api/name-runs` 同步接口继续兼容：200个候选、8批、每批25个，合并后最多12个；新版滑卡页面不再使用这个慢接口。

召回使用“已核验”和“待核验”的本地古籍片段，拒绝其他状态；结果显式展示出处核验状态。模型筛选不等于人工校勘。五行标签只是传统取名参考，不等于判断某个宝宝缺什么或应补什么。

## 部署

Docker Compose 部署：

```sh
cp .env.example .env
# 编辑 .env 中的管理密钥和模型配置，真实凭据不要提交
docker compose up -d --build
docker compose logs --tail=50
```

应用只绑定宿主机 `127.0.0.1:8000`，由现有Nginx提供HTTPS。`构建产物`挂载持久化队列、曝光、收藏和模型配置；容器也包含2018—2021姓名报告资料。Compose可在 `.env` 中用 `NAME_QUEUE_STOCK`、`NAME_DAILY_BATCHES`、`NAME_PRIVATE_TTL` 覆盖上述参数。升级前先备份运行库，勿用仓库数据库覆盖生产库。

单机部署：

```powershell
$env:起名管理密钥 = "替换为随机生成的长密钥"
.\启动服务.ps1 -绑定地址 127.0.0.1 -端口 8000 -工作进程 1
```

生产环境建议：

1. 使用防火墙限制应用端口，只开放反向代理端口。
2. 使用 `部署/Caddyfile` 将外部请求代理到 `127.0.0.1:8000`。
3. 使用 `部署/健康检查.ps1` 定期检查 `/api/ready`。
4. 使用 `脚本/备份数据库.py` 做定期备份，并把备份复制到独立存储。
5. SQLite 模式固定使用一个工作进程；扩展并发前应先迁移到服务型数据库。

健康检查：

```powershell
.\部署\健康检查.ps1 -地址 http://127.0.0.1:8000
```

## 安全和隐私

- 当前计算响应包含八字输入与结果；持久化历史不保存原始时间、换算时间及农历年月日。四柱本身仍可能透露部分出生信息。
- 任务、收藏、反馈和模型接口需要 `X-Session-Key`。网页生成 `web-` 加32位随机十六进制字符的会话密钥；历史仅返回该会话的任务。收藏夹编号为会话密钥的 SHA-256 摘要，原始密钥只通过请求头传递。清除浏览器存储会失去该会话的访问凭据。
- 旧版任务没有所有者映射，升级后不能从公共历史访问，需要管理员在本机处理。不要把真实用户运行库提交至 GitHub。
- 可通过 `起名数据库路径` 指定独立运行库。建库命令遇到已有任务、收藏、反馈或模型调用记录会拒绝重建，请使用新的目标路径。
- 服务不记录真实管理密钥和模型密钥。
- 管理接口使用 ASCII 密钥和常量时间比较。
- 接口包含基本安全响应头、请求限流和输入长度限制。
- 刷卡轻量接口单独限制每IP每分钟240次；原有模型入口仍使用原限流。设备指纹包含安装盐且只使用粗粒度特征，不做画布采集和跨站追踪；它不作为认证凭据。
- 未看租约默认5分钟回收，投递凭据保留30天以支持离线曝光确认；精确曝光记录长期保留以支持去重，清除浏览器数据不能恢复旧身份。
- `.env`、Python 缓存和数据库备份已加入 `.gitignore`。
- 发布前应检查日志、数据库、配置文件和 Git 提交，确认没有真实密钥和真实个人信息。

## 当前限制

- 古籍文本、篇章边界、错字和出处仍需继续人工抽样复核。
- 汉字五行是可替换规则数据，不同流派之间可能存在差异。
- 八字计算需要用户确认出生时间、时区、历法和日界规则。
- 模型接口需要用户自行提供兼容服务和密钥。
- 当前 SQLite 适合单机或低并发场景，尚未完成生产压力测试和完整监控接入。
