# 网络链路优化（2026-10-08）

## 服务器实际业务 API 抽样

在生产 API 容器内通过 HTTP 调用签名鉴权的 `/internal/v1/dispatch`，包含鉴权、限流、数据库查询和响应序列化。使用独立临时测试身份，测试结束已清理测试身份、投递、收藏、回执等记录；没有修改真实用户记录。

这批样本未发现服务器端秒级处理延迟，不能据此排除高峰期、其他筛选条件或公网链路异常。

## 调整

- 云函数已核实为 Active、执行上限 20 秒，内部 HTTPS 转发从 10 秒延长到 18 秒，预留返回时间。
- 小程序 HTTP 模式等待从 15 秒延长到 25 秒；原生 `wx.cloud.callFunction` 没有新增不存在的 timeout 参数。
- 读取、幂等分享创建及带回执编号的 feed.pull，在连接异常或 502/503/504 时最多重试一次，随机退避 250–499 毫秒。冻结请求参数，重试复用原取名回执编号。
- 相同的安全在途请求合并；不同请求继续并发。收藏列表和来源目录读取与身份获取并发，缓存仍按已确认的用户隔离。
- 收藏增删、分享收藏、反馈提交不自动重发；鉴权、参数、限流错误不自动重试，HTTP 原有 401 会话续期流程保留。
- 云函数错误日志只记录动作、耗时和固定错误类别，不记录用户身份、请求内容、签名或密钥。

未增加另一个未经验证的服务地址或主动双发写请求。当前冗余为有限重试、在途合并和已有本地缓存。
