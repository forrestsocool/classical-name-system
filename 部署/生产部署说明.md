# 生产部署

## 方案一：Docker Compose 部署（推荐）

1. 配置环境变量：复制 `.env.example` 为 `.env`，填入长度不少于 16 位的 ASCII `起名管理密钥` 以及模型配置。
2. 启动服务：
   ```bash
   docker compose up -d --build
   ```
   服务将绑定宿主机 `127.0.0.1:8000`，数据库及运行产物挂载在 `./构建产物`。
3. Nginx 反向代理：
   - 参考 `部署/name.sensen.li.conf` 配置 Nginx。
   - 若服务器 443 端口采用 Nginx `stream` 预读模块分流，则 Web server 监听 `8043 ssl http2`，并在 `stream` 映射表中将域名转发至 `127.0.0.1:8043`。
   - SSL 证书引用宿主机 acme.sh 维护的通配符证书（如 `/etc/certs/sensen.li_ecc/`）。
4. 验证服务状态：
   ```bash
   curl -f http://127.0.0.1:8000/api/ready
   ```

---

## 方案二：本地直接部署

1. 设置长度不少于16个字符的 `起名管理密钥`。
2. 执行 `启动服务.ps1`，SQLite 使用一个工作进程。
3. 使用 Caddy 加载 `Caddyfile`，反向代理到 `127.0.0.1:8000`。
4. 使用 `健康检查.ps1` 检查 `/api/ready`。
5. 使用 `脚本/备份数据库.py` 定期备份数据库。
6. 使用 Prometheus 加载 `部署/prometheus.yml`，抓取 `/metrics`；将 `部署/起名系统告警.yml` 放入 Prometheus 的规则目录。
7. 发布前执行生产配置压测：

   ```powershell
   python 脚本/生产压测.py --地址 http://127.0.0.1:8000 --请求数 10 --并发数 3
   ```

   正式域名部署后，将 `--地址` 改为实际服务地址，并保存命令输出作为发布验收记录。

每个场景10次请求，加上起名任务删除，共50次请求。提高数量前应在独立测试环境配置限流额度，默认每分钟60次会影响结果；压测通过不等于正式环境已验收。

Prometheus 配置中的回环地址假设其与应用位于同一主机网络。容器部署需要修改抓取目标和规则文件挂载路径。告警规则仍需配置 Alertmanager 及接收渠道，并实际验证告警投递。Caddy 当前是 HTTP 模板，正式域名须配置 HTTPS。
