# 微信小程序版生产部署

## 1. 准备与配置

部署包括自有服务器上的 PostgreSQL 17、FastAPI 管理与内部 API、独立生产进程，以及 CloudBase 中的一个 Node.js 云函数。

复制项目根目录的 `.env.example` 为 `.env`，填入：

| 配置 | 含义 |
| --- | --- |
| POSTGRES_PASSWORD | 建议随机 64 位十六进制密码，避免 URL 转义问题 |
| 起名管理密钥 | 至少 16 位随机 ASCII，仅用于管理台/监控 |
| GATEWAY_SECRET | 至少 32 位随机可打印 ASCII；云函数与服务器一致，与管理密钥不同 |
| WECHAT_APP_ID | 真实 wx 开头的小程序 AppID；云函数与服务器一致 |
| 起名模型地址 / 起名模型密钥 / 起名模型名称 | 模型配置；也可在后台填写 |
| PRODUCER_SURNAMES | 初始持续生产姓氏，逗号分隔；每个姓氏建立单字、双字两个档案 |
| PRODUCER_DAILY_BATCHES | 默认 480，所有档案共享 UTC 每日派发上限，0 暂停模型调用 |
| PRODUCER_INTERVAL_SECONDS | 默认 10，每批完成后的等待秒数 |
| USER_REQUESTS_PER_MINUTE | 默认每个微信用户 120 次，所有 API 实例共享计数 |

Compose 自动配置内部 DATABASE_URL，不向宿主机发布 PostgreSQL 端口。原生启动时自行设置 DATABASE_URL（PostgreSQL URI）；Python 不自动加载 .env。API 与 producer 必须共享模型配置文件路径，默认持久化在 `构建产物/运行数据/模型配置.json`。文件配置优先于环境变量。

生成随机值示例（每次调用生成不同值）：`python -c "import secrets; print(secrets.token_hex(32))"`。不要将真实配置、密钥或生产数据库加入 Git。

## 2. 迁移 SQLite

1. 备份原数据库，保留原服务代码版本、模型配置和业务文件。
2. 为最终切换停止旧服务写入，用旧版 `脚本/备份数据库.py` 获取一致性备份；将这份快照放到迁移用的 `构建产物/起名系统.sqlite3`。不要只复制活跃 WAL 的主文件。
3. 启动 PostgreSQL 并运行一次迁移：

```sh
docker compose build
docker compose up -d postgres
docker compose run --rm migrate
```

默认源路径通过只读挂载提供。其他文件可显式指定，例如：

```sh
docker compose run --rm migrate python 脚本/迁移PostgreSQL.py --源 /migration/你的备份.sqlite3
```

本机直连迁移：

```sh
python -m pip install -r 后端/requirements.txt
# 先设置 DATABASE_URL
python 脚本/迁移PostgreSQL.py --源 /absolute/path/source.sqlite3
```

迁移在内存中制作 SQLite 一致性快照，检查完整性，在一个 PostgreSQL 事务中建表、导入并逐表核对数量。保留原编号、审核状态、历史任务、收藏、反馈和模型指标，调整 identity 序列；原 owner 和旧合格物料以 legacy_* JSONB 表留档。失败回滚全部新建表与数据；存在 sources 表时拒绝覆盖，不能反复启动迁移容器当作增量同步。

旧匿名收藏不会迁到任何微信用户。旧生成物料仅留档，新的公开库存从已核验古籍重新生产。迁移输出列出导入计数，管理员可从历史统计验证；自动测试也核对行数与序列。

## 3. 启动服务器

```sh
docker compose up -d api producer
docker compose logs --tail=100 api producer
```

访问本机 `http://127.0.0.1:8000/admin`，输入管理密钥，配置模型并检查档案和来源进度。API 默认两个工作进程，producer 为一个独立服务；PostgreSQL advisory lock 防止意外重复生产。

原生运行使用两个终端：

```sh
python -m uvicorn 后端.小程序服务:应用 --host 127.0.0.1 --port 8000 --workers 2
python -m 后端.持续生产
```

Windows 可用 `启动服务.ps1` 启动 API，另行启动生产模块。生产重启后续用来源进度、已审名单和每日额度。无候选来源每小时重查；模型/入库失败指数退避，失败不把候选标记为已审。进程异常退出后预算不退回，避免超发。

公网反向代理只需向云函数开放 `POST /internal/v1/dispatch`，必须 HTTPS 且证书可信。管理页面与 `/api/admin/*` 建议从 VPN、SSH 隧道或运维网段访问。示例见 `小程序网关.nginx.conf.example`；修改域名、证书和管理网段后使用。旧版具体域名配置文件不作为新版部署模板。

- `/api/health`：进程探活，不暴露业务数量。
- `/api/ready`：检查 PostgreSQL、新表与可生成资料，未完成迁移返回 503。
- `/metrics`：管理鉴权后返回库存、今日派发、生产心跳和失败来源。
- `脚本/检查生产进程.py`：供容器检查心跳，模型网络请求期间允许五分钟间隔。
- 旧 `/api/feed/*`、`/api/name-runs` 和 `/static/*` 在新服务中不存在。

## 4. CloudBase 云函数

在目标小程序对应的云开发环境部署 `云函数/nameGateway`。使用支持 Node.js 18 或更新版本的运行时，函数超时设为至少 20 秒；函数内对自有服务器设置 10 秒绝对超时。开启函数所需的外网访问并确认可以到达服务器。

配置函数环境变量：

```text
WECHAT_APP_ID=wx你的真实AppID
CORE_API_URL=https://你的服务器接入域名
GATEWAY_SECRET=与服务器一致的随机共享密钥
```

CORE_API_URL 只接受 HTTPS origin，不带路径、查询、用户名或密码。云函数始终请求固定路径，不转发小程序提供的请求头、身份、URL 或方法，也不跟随上游重定向。不要将函数配置为公众 HTTP 触发入口；客户端用微信云调用。

在微信开发者工具中对 nameGateway 执行“上传并部署：云端安装依赖”，使用已锁定的 wx-server-sdk 版本。正式环境在 CloudBase 控制台设置适当调用配额/并发限制并检查日志。无需在云函数配置数据库或模型密钥。

云函数取得 APPID/OPENID 后签名原始 UTF-8 JSON：
`v1\n时间戳\nnonce\nsha256(body)`（各项之间为换行）。服务端校验五分钟时效、nonce 唯一性和 HMAC；各台主机保持时钟同步。服务器网关密钥轮换时同步更新函数环境变量。

官方接入依据：[CloudBase 在微信小程序中调用云函数](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)。客户端不直连自有服务器，不需要把该业务地址配置为小程序 request 合法域名。这不等于免除小程序自身的备案和审核，或豁免服务器所在地区的域名要求。

## 5. 微信小程序

1. 使用微信开发者工具导入项目根目录，替换 project.config.json 中的 touristappid 为真实 AppID。
2. 在 `小程序/config.js` 填入 envId；gateway 默认 nameGateway。
3. 将小程序与该云开发环境关联，部署上述函数。
4. 预览“发现名字”和“我的收藏”；新条件登记档案后可能需要等生产进程生成首批。
5. 用两个不同微信账号验证收藏隔离、重新打开恢复、断网重试、修改姓氏/固定字/避用字。
6. 在微信后台按实际收集的数据填写隐私说明，配置小程序备案、服务类目、发布审核所需资料，再提交体验版和正式版。

小程序仅储存该微信身份对应的条件和当前卡片缓存。收藏在 PostgreSQL 持久化，可跨设备读取。发卡即记入历史，客户端网络失败重试保留原请求编号；若清空小程序本地缓存，先前已投递但未看的卡片不会重新出现。收藏失败留在当前卡片，允许重试。

当前不提供自由关键词即时生成、管理员入口或浏览器选名页；固定字约束只过滤持久库存。没有符合条件的新名字时明确显示空状态，不临时放宽约束或返回未审稿片段。

## 6. 备份与回退

PostgreSQL 使用名为 postgres-data 的持久卷；**不要使用 docker compose down -v** 清理生产部署。日常备份：

```sh
# 宿主机已安装同主版本或更高版本的 pg_dump，且设置 DATABASE_URL
python 脚本/备份PostgreSQL.py
# 或在 Compose 中直接导出（Linux shell，二进制重定向）
docker compose exec -T postgres pg_dump -U names -d names -Fc > names.dump
```

备份复制到独立存储，并在独立数据库验证 pg_restore。PowerShell 旧版本避免直接重定向二进制备份，可先在容器文件路径导出后 docker cp。同步备份模型配置文件和密钥管理记录。

回退代码前停止 API 和 producer，保存 PostgreSQL 当前备份及切换后的新用户数据。旧 SQLite 无法自动接收新增微信用户、收藏或库存，不能直接把旧文件当成等价运行库。优先修复后向前发布；如确需回退，保留新库用于后续恢复。

## 7. 本地与发布验收

```sh
python -m unittest discover -s 测试 -p "test*.py" -v
node --test 测试/wechat.test.js
python -m compileall -q 后端 脚本 测试
```

真实 PostgreSQL 测试需设置 TEST_DATABASE_URL，测试账户必须能创建临时数据库；测试创建随机 codex_names_test_* 数据库并在结束后删除，仅模拟模型网络调用。没有该变量会明确跳过，不能视为 PostgreSQL 验证完成。

开发环境验收不等于已经部署云函数、调用付费模型或完成微信真机审核。发布前仍需在目标环境验证完整的“小程序 → 云函数 → HTTPS 网关 → PostgreSQL”链路。
