# 五维取象模型补全

目标：仅补全本地知识库中 `energy_profile.supported` 不为 true 的字。原有 2,292 字不调用模型、不覆盖；剩余 5,813 字进入队列，包括旧的 85/15 和五项 20 分占位画像。

## 输入与评分

运行 `python 脚本/补全五行画像.py prepare --output .local/wuxing-backfill/input.json` 生成逐字输入。每字保留主库来源、证据原文，以及原始字源库的全部 `en/sw/swe/d/swf/kxf/hp/gy` 字义和音韵引文，去重但不截断；构形资料、旧规则结论单独提供，避免把规则推断误认为古籍原文。

模型使用服务器现有 `后端.模型接口.读取环境配置()`，密钥只在服务器读取。2026-09-22 检查时为 `gemini-3-flash-preview`。提示词版本为 `wuxing-evidence-v1`，以字形表义和语义取象评分，不让未定义体系的音五行或笔画数混入新分值。

输出五项整数，单项 0–100、合计 100，并解释取象依据；引文用输入编号引用，禁止捏造来源。不足以判断的字记录 `insufficient`，不使用五项 20 分冒充有依据的画像。

## 运行与恢复

```sh
python 脚本/补全五行画像.py run \
  --input /job/input.json --workdir /work \
  --concurrency 3 --batch-size 4 --max-attempts 3
python 脚本/补全五行画像.py status --workdir /work
```

参数强制并发范围 1–4。生产环境另有一个串行名字生产请求，因此补全默认 3 路，为既有生产保留 1 路。不得额外启动第二个补全工作目录来绕过此限制。

同一个工作目录通过操作系统文件锁保证单进程运行。SQLite WAL 持久化逐字状态和每次请求的计数、用量；正常每批 4 字，采用 JSON Schema 约束。每批分别校验每字，合格结果立即保存，仅失败的字逐字重试，最多 3 次。429/网络失败退避，401/403/配置类错误停止新增请求。收到 SIGTERM 后停止派发，等待在途请求保存结果。

重启时使用相同输入、目录和模型，已完成字与资料不足字不会重复调用。原始输入、提示词版本或模型变化会拒绝复用旧检查点。`--limit 16` 供首次试运行，随后去掉 limit 接续全量。

工作目录内：

- `checkpoint.sqlite3`：检查点和调用次数、token 用量，不含密钥。
- `status.json`：已评分、资料不足、失败、待处理数量。
- `model-responses/`：仅保存模型返回正文、结束原因和 token 用量，供格式问题与取象依据复核；不保存请求头或密钥。
- `wuxing_model_profiles.json`：已校验的增量画像及模型、版本、输入摘要、引文依据和时间。

部署目录为 `/opt/classical-name-wechat/构建产物/运行数据/wuxing-backfill`，后台容器为 `qqjm-wuxing-backfill`。查看进度：`sudo docker logs --tail 1 qqjm-wuxing-backfill`。暂停：`sudo docker stop --time 150 qqjm-wuxing-backfill`，重启同一容器可续跑。

## 接入小程序

完成后把输出文件同步为 `汉字五行知识库/data/wuxing_model_profiles.json`，随服务器镜像部署；不要构建小程序端索引。`model_overlay.py` 校验原始知识库 SHA256、分值和推断标记，仅合并缺失的五维画像，不修改古籍原文、原始字源归类或已存在画像。小程序通过受权限约束的接口读取当前姓名结果。

补全过程不发布半成品小程序。原始知识库文件不被改写；回退需同时回退服务器镜像与小程序版本，避免 API 结构不匹配。

注意：补全的是五维取象，不能将模型推断自动写成古籍的五行归类结论。已有“居、方”的分值本次不重算。
