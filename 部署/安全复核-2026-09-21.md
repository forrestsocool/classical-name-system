# 千千嘉名提审前安全复核（2026-09-21）

本次检查覆盖小程序调用代码、CloudBase 网关、Python API、PostgreSQL 数据隔离、生产 Nginx 配置及少量线上异常请求。业务鉴权边界基本完整，已修复参数边界与源站入口配置问题；仍有 Cloudflare 边缘 TLS 和同机其他项目数据库公网入口需要处理。此记录不等于全量渗透测试或审核通过保证。

**实际链路**

小程序通过 `wx.cloud.callFunction` 调用 `nameGateway`，网关取平台提供的 APPID/OPENID，再对请求体、时间戳和随机 nonce 做 HMAC-SHA256 签名。随后经 `name.sensen.li` 的 Cloudflare 边缘节点、服务器 SNI 转发和本站 Nginx 进入 API。小程序包不包含管理密钥或网关签名密钥。源站 API 只映射到 `127.0.0.1:8010`；本项目 PostgreSQL 没有发布宿主机端口。

**已部署的修复**

- 收藏、取消收藏、反馈、收藏分页及比较请求统一限制名字编号为 PostgreSQL 正整数 bigint 范围。此前超大的分页编号会触发数据库异常并返回 503，现在返回参数错误 422。
- 本站 TLS 移至独立的 `127.0.0.1:18043`，`/etc/nginx/nginx.conf` 的 stream map 中只将 `name.sensen.li` 改指向该端口，避免共用 8043 时继承其他站点旧 TLS 策略。源站只接受 TLS 1.2/1.3，移除旧密码套件。
- 网关请求体上限 16KB，其他本站请求上限 32KB；缩短请求头、请求体和代理超时。HSTS 在错误响应上同样生效，隐藏 Nginx 版本。
- 管理 API 限制为本站合计 5 请求/秒、突发 20；网关为本站合计 40 请求/秒、突发 80。现有按 OPENID 的每分钟 120 次业务限制保留。SNI stream 未透传真实来源 IP，因此这里明确采用站点总量限制，不能描述成按客户端 IP 限流；业务增长时需结合流量调整容量。
- 限流返回 429 JSON，保持云函数错误处理兼容；旧 `/api/test/` 通道在 Nginx 再次封闭，`/metrics` 继续禁止公网访问。

仓库中的 `部署/name.sensen.li.conf` 对应生产端口 8010。通用 `docker-compose.yml` 的默认宿主机映射仍为 8000；重新部署到其他环境时必须统一实际映射、Nginx upstream 和 stream map，不能只复制站点文件。

本次未修改或重新上传正在提审的小程序包，未更改云函数部署、名字数据或用户收藏。API、生产进程、数据库均已复查为 healthy。部署备份含旧业务文件、Nginx 主配置、站点配置和旧镜像标签，位于服务器 `/opt/classical-name-wechat/构建产物/数据库备份/security-20260921-155558`。回滚要同时恢复 stream map 和站点配置，先运行 `nginx -t`，再 reload；仅回滚业务文件不足以回滚运行中的 API 镜像。

- 公网接口与响应保护共 27 项检查全部通过：管理接口匿名/错误密钥请求 403，未签名/篡改/过期请求 401，签名重放 409，额外 owner 字段和异常参数 422，大请求 413，禁用测试接口和调试文档 404。有效签名的来源目录请求 200。测试只使用专用合成身份读取来源目录，没有操作真实用户收藏。
- 实际握手确认源站 TLS 1.1 返回协议版本错误，TLS 1.2/1.3 可用。经正确 SNI 验证证书，未关闭证书校验。

**尚未关闭的风险和检查边界**

1. **Cloudflare 边缘仍接受 TLS 1.1。** 源站已加固，但域名解析指向 Cloudflare，访客连接的协议由边缘设置决定。需要在 Cloudflare 的 `sensen.li → SSL/TLS → Edge Certificates → Minimum TLS Version` 选择 1.2，并核查回源模式为 Full (strict)。最低 TLS 版本的普通设置作用于整个 zone；只对 `name.sensen.li` 单独设置需确认 Advanced Certificate Manager 权益。本次没有 Cloudflare 控制台访问或适用的管理凭据，未更改该设置。[Cloudflare 官方说明](https://developers.cloudflare.com/ssl/edge-certificates/additional-options/minimum-tls/)
2. **同机其他项目的 5432 端口可从公网建立 TCP 连接。** 宿主机防火墙也显式放行该端口。这不是本小程序的 PostgreSQL。本次没有登录、读取或探测该数据库的口令；公网可连不代表已证实未授权读取，但应优先改为可信 IP 白名单或通过 SSH 隧道连接，实施前要确认其他项目的实际客户端。其他 Redis、Qdrant、Selenium/VNC 端口也映射到公网网卡，本次从当前网络连接未成功，不等于所有网络和 IPv6 都不可达；没有擅自调整其他项目端口。
3. 管理入口仍在公网，依赖强管理密钥和新增限流，没有额外 MFA。密钥长且比较采用恒定时间实现，管理前端不将它写入浏览器持久存储。若需要更高隔离，可将管理入口置于 VPN/身份访问代理后，同时保留云函数入口可达。
4. 没有执行 DDoS、密码爆破、整机漏洞利用或全量依赖/操作系统 CVE 扫描，没有验证所有 IPv6 路径和 Cloudflare WAF 规则。不能据此承诺整台服务器不存在其他漏洞。历史在聊天中提供过的 AppSecret/管理 API Key 建议在对应平台轮换；本次没有将它们添加到代码或报告中。

**防中间人抓包能力**

已具备的是平台身份校验、HTTPS、服务端 HMAC 签名和 nonce 防重放。HMAC 保护云函数到源站请求的真实性和完整性，并不是请求内容加密；也不能因此承诺安装了代理证书或被控制的终端看不到明文。

微信官方提供 `wx.getUserCryptoManager().getLatestUserKey()`，可取用户加密密钥、IV、版本和有效期。这是实现额外加密协议的基础接口，需要前后端配合，不是给现有 `wx.cloud.callFunction` 加一个配置即可自动启用。若接入，应完整设计请求和响应加密、完整性验证、密钥更新、防重放及旧版本兼容，不将长期密钥放入小程序包。[微信官方 API 定义与文档入口](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)

腾讯云 WAF 的“小程序安全”提供私有协议加密等能力，自动接入需小程序管理员扫码授权、源站域名接入 WAF，并验证后发布；它属于增值能力，未试用账号可有 7–15 天试用权益。官方文档未证明现有 `callFunction` 链路可直接由该功能覆盖，因此不能声称已开通或适配完成。本次没有购买套餐或改变提审版网络协议。当前优先处理上述入口风险；确有防代理读取业务内容的要求时，再对适配方案做体验版验证。[腾讯云官方接入说明](https://cloud.tencent.com/document/product/627/102484)

审核测试期间应继续保持正常鉴权和业务行为，不给审核 IP 放开管理权限，也不靠拒绝审核流量掩盖问题。
